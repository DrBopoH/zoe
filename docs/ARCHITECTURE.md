## 1. Принципы

1. **Локально и для одного пользователя.** Бэкенд слушает `127.0.0.1`, CORS пускает только перечисленные Origin; тексты внутренних ошибок возвращаются клиенту (это осознанно: приложение не публичное).
2. **Две базы с разной ценностью.** `cache.db` одноразовая и восполнимая, `core.db` хранит то, что нельзя терять (лица, алиасы, связи, ручные правки). Парсеры и синхронизация пишут только в кеш. Единственный путь «кеш → статика» это `syncAliases` (см. [§7](#7-лица-алиасы-связи)).
3. **Источник правды вне базы.** Всё, что импортировано, лежит ещё и в файлах `.zoe`; сброс кеша не теряет данных (§5).
4. **Идемпотентность.** Повторный импорт той же или перекрывающейся выписки не создаёт дублей: ID операций стабильны (`stmtkit.StableID`).
5. **Вычисляется при чтении.** Баланс ICU, накопленный купон, вид операции Binance, «свой счёт» и `resolved_user_id` в базу не пишутся, а считаются на лету по текущим правилам.
6. **Явная ошибка вместо догадки.** Неизвестный вид операции ICU, непустой раздел корпоративных операций, непонятный файл дают ошибку импорта, а не эвристику.
7. **Один механизм на одно дело.** Перед новым кодом проверяй, нет ли уже такого пути (HTTP-хелперы, реестр банков, `usePaged`, `stmtkit`).

## 3. Бэкенд

### 3.1 Запуск (`main.go`)

`godotenv.Load()` (необязательно) → токены банков из `MONO_TOKENS`/`MONO_TOKEN`, `RAIF_TOKENS`/`RAIF_TOKEN` через `api.ClientsFromEnv` → `db.NewStorage(cacheDBPath, coreDBPath)` → `api.NewServer(storage, monoClients, raifClients)` → `SetBinance(binance.NewClient())` → `ALLOWED_ORIGINS` → `http.Server` (`ReadHeaderTimeout` 10 с, `ReadTimeout` 2 мин на загрузку выписки, `IdleTimeout` 2 мин). По Ctrl+C/SIGTERM сервер дожидается запросов (10 с) и закрывает обе базы (сброс WAL). Переменные окружения: см. [README](../README.md#настройки-окружения-бэкенд).

### 3.2 HTTP-слой (`pkg/api`)

- `routes.go` — **единая таблица маршрутов**; CORS (`EnableCORS`) навешивается один раз на весь mux, поэтому новый маршрут нельзя «забыть» защитить.
- `httpx.go` — общие ответы: `writeJSON`, `writeOK` (`{"status":"success"}`), `writeMsg`, `fail`, `failErr` (500, текст в ответе), `readJSON` (лимит тела 1 МБ, при ошибке сам отвечает 400), `allow` (проверка метода → 405). Тела выписок читают свои хендлеры (лимит 32 МБ).
- CORS: запрос **без** `Origin` пропускается (curl, прокси); запрос с неизвестным Origin получает 403.

### 3.3 Версия данных

`Storage.Version()` растёт при любой записи (кеш или статика). Он отдаётся в `/sync/status` как `stats.data_version`. Фронт опрашивает лёгкий статус каждые 2 секунды и перезагружает тяжёлые данные только при смене версии.

## 4. Данные и базы

SQLite (драйвер `modernc.org/sqlite`, без CGO), открывается с `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=10000`, `foreign_keys=1` через DSN (применяется к каждому соединению пула). Записи сериализуются мьютексами `cacheMu` и `coreMu`.

### cache.db — одноразовый кеш

| Таблица | Содержимое |
|---|---|
| `accounts` | счета: id, имя, баланс, тип, валюта, IBAN, маска PAN |
| `transactions` | операции: время (unix), описание, контрагент (имя, IBAN, ЕДРПОУ), MCC, суммы, комиссия, кэшбэк, `is_hold` |
| `sync_coverage` | снятые отрезки времени по счетам (`From == HistoryStart` значит «история снята до дна») |
| `icu_flows` | журнал брокерского отчёта ICU |
| `market_bonds` | облигации из публичных источников: `source` (`nbu`/`ust`), `id` (ISIN/CUSIP), погашение, ставка, номинал, доходность и дата последнего аукциона |
| `binance_ledger` | журнал выписки Binance, строка как есть |
| `binance_minutes` | оценка портфеля Binance по минутам, ₴ |
| `binance_state` | служебные ключи (состояние последней «Разведки») |

### core.db — постоянные данные

| Таблица | Содержимое |
|---|---|
| `users` | Лица: id, имя, роль, аватар |
| `user_aliases` | алиас → Лицо (`alias_key = lower(trim(alias))`, ключ считает Go, чтобы Unicode не расходился с SQLite) |
| `alias_accounts` | запомненная структура алиаса: alias → IBAN → PAN (живёт и у бесхозных алиасов) |
| `alias_bans` | теневые баны: что кешу нельзя подхватывать для привязанного алиаса |
| `iban_pans` | глобальный факт «карта принадлежит этому IBAN» |
| `iban_masks` | скрытый вид IBAN; `custom=1` означает свой псевдоним счёта |
| `account_overrides` | ручные правки счёта: IBAN, PAN, кредитный лимит, даты открытия и закрытия |
| `bonds` | справочник облигаций (ISIN, погашение, ставка, номинал) |
| `macro_series` | кеш макро-рядов НБУ: `series`, `dt` (YYYY-MM-DD), `value`, `updated_at`; ряд заменяется целиком при каждом обновлении |
| `market_lists` | свои списки бумаг рынка: `name` (`icu`), `isins` — токены `ISIN[=цена][~ytm]` через пробел, `updated_at` |

`initCore` умеет мигрировать старую схему (`user_accounts`, алиасы без `alias_key`).

### Жизненный цикл счёта

Банковские API дат открытия и закрытия не отдают. Открытие = самая старая операция, но только когда история снята целиком. Закрытие = счёт пропал из ответа банка (дата — последняя операция). Ручная дата в `account_overrides` приоритетнее выписки; после даты закрытия операций не может быть.

## 5. Источники и импорт

### Формат `.zoe` (`pkg/source`)

Один файл — один импорт (или снимок API) одного счёта за один период. Внутри **уже разобранные данные**, а не исходный PDF/CSV: «Загрузить» не парсит заново, а кладёт готовое в базу. Поля: `Name` (имя исходного файла = алиас, задаётся один раз), `Created`, `Hash` (отпечаток содержимого без `Name`/`Created`/`Origin`; одинаковые данные под другим именем — дубль), `Kind` (`bank`, `binance`, `icu`, `binance-series`), `Origin` (`csv`, `pdf`, `report`, `binance`, `api`), `AccountID`, `Card` (ключ папки), период (`From`/`To`), `Spans` (отрезки, уже снятые с API: после загрузки источника синхронизация их не опрашивает), плюс данные: `Txs` (банки), `Rows` (Binance), `Flows` (ICU), `Series` (минутный ряд Binance). Файл пишется атомарно (временный файл, затем переименование) с правами `0600`; JSON больше 1 МБ сжимается gzip (читаются оба вида). Папка источников делится по номеру карты (`516875******8629`, не по IBAN: один IBAN может нести два PAN); `ECONOMIC_SOURCES_DIR` переопределяет путь.

### Конвейер импорта

1. `POST /sources/inspect` (multipart) → `parseSource` определяет тип по содержимому: `binance.IsStatement` → Binance; `icu.IsReport` → ICU; PDF → Privat; `novapay.IsStatement` → NovaPay; иначе CSV Raiffeisen. Ничего не пишется. Ответ описывает счёт, период, пересечение с имеющимся и список `problems`: `other_account`, `exists`, `duplicate` (блокируют), `alias`, `no_match` (требуют решения).
2. `POST /sync/import-csv` применяет решения пользователя (`mode`, `account`, `alias`, `force`) через `enforceImportRules`, сохраняет файл `.zoe` и вызывает `applySource` — **единый путь** и для импорта, и для «Загрузить».
3. `applySource` пишет в кеш и обновляет статику через `syncAliases`.

`migrateLegacy` переводит старые «сырые» файлы кеша источников в `.zoe`; оригиналы уезжают в `_legacy`, что не разобралось, остаётся и попадает в отчёт.

### Идентификаторы

- Банковский счёт: `<тип>_<IBAN>`, а без IBAN `<тип>_<карта>`.
- ICU: `icu_<цифры номера договора>` (`db.ICUAccountID`): в отчёте нет IBAN, договор единственный стабильный ключ.
- Binance: `BN<id пользователя>`; профиль берётся из выписки.
- Операции: `stmtkit.StableID(prefix, key, seen)`. Номер строки файла в ключ **не входит** (сдвиг строк между выгрузками создавал бы дубли); одинаковые операции в одну минуту различаются порядковым суффиксом. Менять формат ключей нельзя: повторный импорт создаст дубли.

### Парсеры

| Пакет | Вход | Особенности |
|---|---|---|
| `privat` | PDF (через `pdftext`) | сумма операции берётся как в карточной колонке; комиссии не пересчитываются |
| `raif` | CSV | семантику комиссий не менять |
| `novapay` | CSV | ПІБ, ІПН и паспорт из шапки не читаются; берутся счёт, карта, остаток |
| `icu` | PDF (текстовый слой) | итоги раздела 1 служат контрольными суммами; расхождение = отказ импорта |
| `binance` | CSV выписки | читаются все строки как есть; смысл строки решает `ledger.go`; часовой пояс из имени файла |

Время в выписках киевское (`stmtkit.Kyiv`), не зависит от пояса сервера. Парсеры и математика графика не должны зависеть от часового пояса машины; при правках времени прогоняй тесты ещё и под `TZ=America/New_York` и `TZ=Asia/Tokyo`.

## 6. Синхронизация по API

«Разведать» (`POST /sync/full[?save=1]`) запускает `runFullCrawler`: каждый ключ Monobank и Raiffeisen обходится параллельно (`crawlBank` с `bankSpec`), затем при наличии выписки Binance строится минутный ряд оценки (`crawlBinance`). У банков разные лимиты: Monobank — пауза 61 с между запросами одного ключа, лимит ответа 500 операций; Raiffeisen — 30 с, лимит ответа неизвестен.

**Автозапись в источники.** С `save=1` после обхода (`saveToSources`) вызывается тот же `saveAPISources`, что и у `/sources/save-api`: снятое с API пишется в файлы-источники (повтор без новых данных ничего не плодит). Отменённый обход (сброс кеша) не пишет. Итог идёт в `last` (`autosave`, `saved`, ошибки записи — в общем списке ошибок). Фронт: `useSync.js` (общее `isSyncing`, галочка `zoe.sync.autosave`, по умолчанию включена), `SyncButton.vue` во вкладке Смета и в окне «Выписки», запуск — `startSync` из `App`; кнопки в шапке больше нет, у логотипа остаётся пульсирующая точка.

**Обход счёта (`walkAccount`)** идёт от «сейчас» назад окнами (30 дней) только там, где `sync_coverage` не знает ответа:

- место уже снято → прыжок без запроса; `From == HistoryStart` → история целиком, конец;
- окно, упирающееся в снятое, обрезается по его краю;
- свежий кеш = один запрос (хвост); отстал на месяц = окна по дыре; прерванная выгрузка продолжается с последней дыры;
- серия пустых окон объявляет начало истории; пустой снятый отрезок идёт в счёт «пустого хвоста».

Ошибки классифицируются (`errKind`): сеть (`errOffline`, остальные счета ключа не опрашиваются) отличается от отказа банка; сброс кеша отменяет обход (`errStopped`) и не считается сбоем. `fetchWithRetry` повторяет попытки. Структурированный прогресс (`progress.go`: клиент → счета → таймлайн) отдаётся в `/sync/status`; фронт ничего не парсит из строки статуса.

`/sync/wipe-cache` сначала снимает идущий обход (`abortSync`), потом чистит кеш; `core.db` не затрагивается.

## 7. Лица, алиасы, связи

Словарь:

- **Алиас** — имя из банка (владельца или контрагента); ключ `lower(trim)`. Расширение в алиасе (`Имя.csv`) значит «из файла-импорта» и **намеренно сохраняется**: так IBAN такого алиаса не сливаются с одноимённым API-алиасом.
- **Лицо** знает только названия своих алиасов; всё остальное идёт через алиас.
- **Эффективная структура алиаса** = (статика ∪ кеш) − баны. Зелёное: подтверждено кешем; жёлтое: только статика.
- **Теневой бан** запрещает кешу подхватывать связь, которую пользователь убрал руками. Снимается при отвязке алиаса или ручном возврате связи.
- **PAN-сирота** — карта, которой нет среди своих счетов. **Псевдо-алиас** — контрагент без имени, известный только по карте.
- **Резолвер** — модалка алиаса (`AliasDrumModal`): барабан своих карт, таблица операций, справа все карты; карта перетаскивается на строку контрагента.

**Связь IBAN ↔ PAN** — глобальный факт (`iban_pans`), не привязанный к алиасу. IBAN алиаса автоматически тянет свои карты (из `iban_pans` и кеша) минус баны. `UnlinkAccount` банит IBAN и каскадом его карты; `LinkAccount` обязан снимать баны и с IBAN, и с его карт (регрессия закрыта тестом `TestRelinkIbanRestoresPans`).

**Кеш → статика**: `syncAliases` — единственный путь. Только для алиасов, уже привязанных к Лицу; только то, что кеш подтверждает; мимо теневых банов. Вызывается при старте и после импорта/синхронизации.

**Сравнение карт**: `idKey` (первые 4 + последние 4 цифры); для масок вида `414949****72` слабый ключ `looseKey` (BIN 6 + последние 2). **Реализация на Go (`db/util.go`) и JS (`frontend/src/utils/personLayout.js`) должна совпадать**; менять только парой.

**Индекс кеша** (`loadCacheIndex`, зеркало на фронте `buildCacheIndex`): имя аккаунта в банке → его IBAN и все PAN; контрагент операции (`counter_name`, иначе контакт из description) → `counter_iban`. Сравнение точное, без LIKE.

**«Свой счёт»** (`db/own.go`): номер контрагента берётся из `counter_iban` и из текста операции (имя/описание); счёт самой операции не считается; если номера нет, ищется по счетам и картам алиаса, но только когда среди них ровно один наш счёт, кроме счёта операции. Результат — `Transaction.OwnAccountID` (на чтении). Перевод между своими счетами не входит в приход/расход ни в истории, ни в Смете.

## 8. Брокер ICU и облигации

- Данные счёта — только брокерский отчёт: журнал в `icu_flows`, баланс нигде не хранится, а считается из журнала и справочника облигаций (`ComputeState`).
- Виды записей журнала (`icu_flows`): `deposit`, `withdraw`, `buy`, `sell`; покупка списывает деньги с накопленным купоном (`isin`, `qty`). Купоны и погашения в журнале **не хранятся**: они вычисляются из справочника облигаций.
- Справочник `bonds` (в `core.db`, один на всех): ISIN, название, погашение `YYYY-MM-DD`, ставка (% годовых), номинал (1000 ₴ по умолчанию). Купон выплачивается раз в 182 дня, даты отсчитываются назад от погашения (`couponPeriodDays`), размер купона = номинал × ставка / 100 / 2. Выплаты (`PayEvent`, вид `coupon` или `redemption`) вычисляются на чтении; `Done` — уже прошла.
- Привязка к Лицу — обычным путём, через алиас по имени файла.
- На фронте: `historyOrder.js` задаёт логический порядок внутри дня (у отчёта нет времени: полдень-заглушка, в таблице скрыт), `useCapitalChart` собирает операции облигаций в справочные строки (`memo`), которые видны в истории, но в приход/расход не входят.

### Общий движок графиков (`utils/chartView.js`, `composables/useChartView.js`)

- Интерактив SVG-графиков написан один раз. `utils/chartView.js` — чистая математика: `zoomWindow`/`panWindow` (окно по оси X с якорем и пределами размаха), `panY`/`zoomY` (ручная вертикаль в пределах крайностей), `easeRange` (шаг плавного догона нарисованной вертикали до цели), `quantile` и `robustRanges` (подгонка вертикали по перцентилям, чтобы выброс не сплющивал шкалу, плюс `ext` — крайности по всем данным).
- Цвет линии по значению: в `SERIES` у ряда поле `gradient { from, to, stops:[[доля, цвет, прозрачность]] }`, `buildMacroChart` отдаёт `line.gradient` (вектор в пикселях графика), `MacroPanel` рисует `linearGradient` в userSpaceOnUse; сейчас так окрашены `crypto_fng` (голубой страх — серый середина — янтарь жадность) и `us_vix` (серый около 20, выше голубой, ниже 14 янтарный), `us_sentiment` — светофор красный (≤ 50) → жёлтый (75) → зелёный (≥ 100); `noLog` у ряда прячет переключатель лог-шкалы.
- Шкала значения заложена в движок: `scaleOf('linear'|'log')` (`fwd`/`inv`), `logTicks` (деления m×10^k), `robustRanges({ log })`, `scaleTicks(mode, lo, hi)` в `growthChart.js`. Вертикаль движка (`yShown`, `target`, `ranges`) живёт в шкальном пространстве (при log — натуральный логарифм), так что сдвиг, масштаб, плавная подгонка и инерция не знают про шкалу; `vAt` возвращает обычное значение. График получает `scaleMode` и сам переводит значения через `fwd` (`buildMacroChart({ scale })`, `macroRanges({ log })`). `MacroPanel` даёт переключатель и проп `log` (стартовая шкала); `canLog` — все значения > 0. `GrowthChart` и `CandleChart` пока линейные (опция `scale` не передаётся), включить можно так же.
- `useChartView({ width, height, pad, autoX, ranges(view, scale), spans, resetOn, bounds, inertia, scale, canLog })` держит состояние окна и вертикали, плавную анимацию (rAF), колесо, перетаскивание, наведение, сброс и переводит пиксель мыши в данные (`tAt`, `vAt`). График сам даёт только данные и границы: окно по умолчанию (`autoX`), диапазоны вертикали для окна (`ranges(view)`) и функцию построения линий. Ось X — годы от сегодня (как у роста вложения), поэтому одни и те же `timeTicks` и `niceTicks` рисуют подписи у разных графиков.
- Слой цикла Беннера: `components/BennerBands.vue` (`layer="bg"` — колонки за данными, `layer="strip"` — полоса в подвале) + `utils/benner.js` (`bennerPhase`, `bennerSpans`); слой общий и годится любому графику с осью времени (`xOf(ms) → px`, края окна `fromMs`/`toMs`, поля; свечи переводят слоты через `msToSlot`/`slotToMs`), но подключён только к графикам биржи: у `MacroPanel` проп `benner` по умолчанию `false`, `MacroStocksView` включает его, `GrowthChart` и `CandleChart` слой не используют. Цвета яркие (#fb7185 / #fbbf24 / #34d399). Это курьёз, не сигнал (подписано в интерфейсе).
- Подключены: `GrowthChart.vue` (рост вложения), `MacroPanel.vue` (макро-ряды) и `CandleChart.vue` (свечи капитала). Ловушка: переменная `dragY` объявляется до `watch(target, …, { immediate: true })`, иначе в dev TDZ. Необязательные возможности: `bounds()` — границы окна по X (`clampWindow`), `inertia` — бросок вбок доезжает по инерции (`inertiaStep`); горизонтальный жест тачпада двигает окно, `eventT(e)` отдаёт ось X под событием (клик без движения), при сдвиге окна под неподвижной мышью подсказка следует за ней.

### Макро НБУ (`market/macro.go`, `db/macro.go`, `GET /api/macro`)

- Источник `macro` («Ставки и инфляция · НБУ») в `Feeds()`. Адреса проверены живым curl: `bank.gov.ua/NBUStatService/v1/statdirectory/key?json` — все ставки одним запросом (ежедневно с 1992 года; `id_api`: `KEY_PolicyRate`, `KEY_RateOvernightCD`, `KEY_RateOvernightLoans`, поле `value`), и `…/inflation?period=m&start=YYYYMMDD&end=YYYYMMDD&json` — только окнами (целиком сервер отвечает 400 «надто великий dataset»); окна по 10 лет с 2000 года, данные начинаются с 2007.
- Ставки сжимаются до дат смены значения (`changePoints`). Из инфляции берутся только строки итога: `ku` пуст, `mcrd081 = Total`, `mcrk110` пуст, название «Індекс споживчих цін» (общая) или «Базовий …» (базовая); `tzep` `DTPY_` = г/г, `PCPM_` = к предыдущему месяцу; остальное (цены производителей, регионы, категории, накопительные `PCCM_`/`PCCP_`) отбрасывается и считается в `Skipped`.
- Сбой одной части не стирает другую: что скачалось, то сохраняется, ошибка идёт в `Result.Error`. Ряд в базе заменяется целиком (`SaveMacroSeries`), остальные ряды не трогаются.
- Фронт: `composables/useMacro.js` (читает `/macro`, перечитывает по `data_version`), `utils/macro.js` (`valueAt`, `realRate` по Фишеру, `macroSummary`, `buildMacroChart`), `components/MacroPanel.vue` (слой цикла Беннера, пропс `benner`; поле `MACRO_PAD.b` 36 даёт место полосе); колонка «Реальная» в `MarketView` (`signed` в `COLUMNS`: ноль и минус не считаются «пустым» при сортировке).

### Рыночные облигации (`pkg/market`, `db/market.go`, `api/handlers_market.go`)

- Источники: `https://bank.gov.ua/depo_securities?json` (реестр, ОВДП отбираются по префиксу ISIN `UA4000`), `https://bank.gov.ua/NBU_ovdp?json&date=DD.MM.YYYY` (результаты аукционов Минфина; дата строго `DD.MM.YYYY`, день без аукциона даёт `[]`; перебираются последние 14 дней) и `…/v1/accounting/od/auctions_query` FiscalData (аукционы США за 3 года, CUSIP без дублей, побеждает поздний аукцион).
- Ключей нет, запросы только на чтение. Обновление **только по запросу**, отдельным процессом рядом с обходом банков: запускается вместе с «Разведать» (`POST /api/sync/full`, даже если у банков нет ключей) или сам (`POST /api/market/sync[?source=nbu|ust]`, ответ сразу, 409 если уже идёт). Список — `GET /api/market/bonds[?source=&q=]`.
- Источники — «фиды» (`market.Feed`: `ID`, `Title`, `Fetch`, список `Client.Feeds()`): идут **параллельно** и не знают друг о друге, упавший не мешает другому. Новый источник (ФРС и т.д.) — ещё одна запись в `Feeds()`, без новых маршрутов и тостов. Фид бумаг заполняет `Fetch` (`[]Security` → `market_bonds`), фид числовых рядов — `Series` (`[]SeriesPoint` → `macro_series`, `Storage.SaveMacroSeries`), у фида есть `Unit` («бумаг»/«точек») для окна процесса и тоста; `?source=` проверяет `market.IsSource`.
- Состояние — ключ `market` в `/api/sync/status` (`running`, `started_at`, `feeds[]` со `state` `queued|fetch|done|error`, `fetched`, `skipped`, `error`, и `last` с итогом). Он **не смешан** с банковским `progress`: свой итог, своя блокировка и свой отмена-контекст. Сброс кеша (`abortSync`) отменяет и этот процесс и ждёт его до 3 с, чтобы он не дописал данные в чистую базу.
- Ход: `Feed.Fetch(ctx, rep Reporter)`; источник сообщает `rep(pct, note)` («аукционы: 07.11», 46 %). В `feeds[]` это `pct`/`note`: с процентом фронт рисует заливку, без процента (`pct` 0) — бегущие полосы. Для длинных выгрузок (например, помесячная ставка США за много лет) источник просто вызывает `rep`.
- Окно процесса: `MarketPanel.vue` (в `ToastStack`) висит, пока `market.running`, как окно синка банков, но отдельное; крестик глушит именно этот запуск (`started_at`). Логика показа — `utils/marketPanel.js` (`marketPanelOpen`, `feedView`).
- Фронт: `utils/marketNotice.js` решает, что показать, по `market.last.finished_at` (итог до перезагрузки страницы не показывается); на каждый источник свой тост: зелёный по таймеру или красный до закрытия.
- Разбор терпимый: поле ищется по нескольким именам, `null`/пусто — нет значения, число принимает `16,44`. Запись без идентификатора пропускается (`Result.Skipped`). Форматы сверены по документации, а не по живому ответу, поэтому при смене полей источника правится список имён в `nbu.go`/`ust.go`.
- Сохранение — `ON CONFLICT … DO UPDATE`: пустое значение не затирает известное (реестр даёт условия, аукцион — доходность). Погашенные бумаги остаются. `WipeCache` стирает и эту таблицу.
- Связь с ICU: `bondTerms()` берёт справочник `core.bonds` и добавляет скачанные гривневые ОВДП со ставкой > 0 и датой погашения; **своя запись всегда главнее скачанной**. Редактор справочника (`ListBonds`, `/api/icu/bonds`) показывает только свои записи.
- Автозаполнение: форма «+ ОВДП» в редакторе справочника (`IcuBondsEditor.vue`) по 12-значному ISIN запрашивает `GET /api/market/bonds?source=nbu&q=<ISIN>`, ищет **точное** совпадение (`utils/bondLookup.js`) и подставляет только пустые поля: погашение, ставку, название; набранное руками не затирается, бескупонная ставку не заполняет. Нет в кеше — подсказка «нажми «Разведать» или введи вручную».
- Не входит: депозитные сертификаты НБУ и ключевая ставка — это макроданные следующих коммитов билда 2.

## 9. Binance

Источник движений — только официальная выписка (Wallet → Transaction History → Export); ключа API нет. Публичные цены берутся с `api.binance.com` (минутные свечи, `Prices`, `Symbols`); клиент соблюдает лимиты и повторяет запросы.

- `statement.go` читает все строки; `ledger.go` решает, что строка значит для портфеля: внешние движения (депозит, вывод, P2P, бонус, dividend) становятся операциями счёта, остальное (сделки, комиссии, конвертации, пыль, стейкинг) остаётся внутренним движением кошелька.
- Кошельки: Spot, Funding, Strategy, USD-M Futures — **все четыре** считаются частью портфеля по рыночной цене, поэтому график двигается по ходу работы ботов и фьючерсов. Earn в выписке своих строк не имеет и виден по подписке/выкупу.
- `moves.go` собирает переводы между кошельками: две строки журнала (минус в одном, плюс в другом) парятся по монете и сумме в окне нескольких секунд; одиночная половина достраивается по названию операции. Это справочные строки истории («откуда → куда»), капитал не меняют. `swaps.go` — обмены (Convert, пыль → BNB, стейкинг), `trades.go` — покупки и продажи.
- `series.go`: остатки известны из журнала на любой момент (`Timeline`), история портфеля = оценка остатков по минутным свечам монет и паре USDT/UAH. Ряд подписан хешем журнала (`Sig`): сменился журнал — ряд устарел. После нового CSV ряд обрезается с минуты первой **новой** строки и дорисовывается; повтор того же CSV ряд не трогает; новая строка раньше начала ряда — ряд с нуля.
- Баланс счёта = последняя точка ряда. На карточке Binance показывается в долларах с эквивалентом в гривнах (курс USDT/UAH из последней «Разведки»).
- «Сброс кеша» сносит и Binance; «Загрузить» возвращает журнал из `.zoe`, следующая «Разведка» строит оценку. Ряд сохраняется в `.zoe` как `binance-series` (сбор занимает 10–20 минут).

```
                                     └─ да → fetchData(): /accounts /transactions /users …
```

`App.vue` держит `accounts`, `transactions`, `users`, прогресс синхронизации и передаёт их во вкладки как props. Тосты (`useToasts`) показывают итог синка. Потеря связи с бэкендом — отдельная плашка, не «синк упал».

### 10.2 API-слой (`utils/api.js`)

Единственное место с `fetch`: `API_BASE` (`VITE_API_BASE`, по умолчанию `http://localhost:8080/api`), `apiSend(method, path, body)` (JSON), `apiUpload` (multipart), `apiGetJson`, `apiJson`, `q` (= `encodeURIComponent`). Ошибка не-2xx превращается в `Error` с текстом бэкенда. Прямых `fetch` в компонентах быть не должно.

### 10.3 Браузерное хранилище (`utils/storage.js`)

`storageGet/storageSet/loadJSON/saveJSON` — безопасные обёртки над `localStorage` (приватное окно, очищенные данные: не бросают). Используются только для удобств: активная вкладка (`economic_active_tab`), таймфрейм (`zoe.candle.tf`), порядок карт (`persons_card_order`). Всё, что важно сохранить, живёт на бэкенде.

### 10.5 Граф алиасов (`utils/personLayout.js`)

Главная клиентская логика: из `users`, `alias-structures`, счетов и транзакций строится граф — для каждого Лица группы банков, IBAN, карты, подтверждённость, PAN-сироты. Содержит зеркало бэкенда (`idKey`, `looseKey`, `isPanLike`, `buildCacheIndex`): **менять вместе с `db/util.go` и `db/resolve.go`**. `resolveRows.js` готовит строки резолвера (исходящие: только переводы людям; входящие: всё, кроме юрлиц и магазинов; банк как «контрагент» — комиссия, не человек). `personName.js` подменяет алиас контрагента на Лицо: кто чей, решает бэкенд (`resolved_user_id`), фронт только подставляет.

### 10.6 Свечной график

- `composables/useCapitalChart.js` собирает вход: гривневые счета, их операции, крипто-счета, операции облигаций (`bondOps`) и выплаты (`payEvents`). `pickedIds` пуст — все счета (Смета), иначе выбранные карты (Операционная).
- `components/CandleChart.vue` — реактивная часть: таймфреймы, подгрузка свечей Binance чанками (кеш по таймфрейму), выбор свечи кликом. Масштаб, сдвиг, инерция и вертикаль ведёт общий движок (`useChartView`): ось X — слоты от правого края данных (`candleBounds`, `candleWindow`, `candleSpans`, `visibleSlots`, `candleYRanges` в `utils/candleMath.js`), поэтому подгрузка истории слева окно не двигает; рисуются только видимые свечи плюс слот запаса; вертикаль по свечам в окне, ручной сдвиг и Shift+колесо в пределах крайностей; ширина svg измеряется `ResizeObserver` (скрытая вкладка в `KeepAlive` даёт 0 — держится прежняя). Колесо над ним обрабатывается самим компонентом (`data-wheel="own"`).
- `utils/candleMath.js` — **чистая математика без Vue и DOM** (таймфреймы `TFS`, начала дня/недели, корзины, «красивые» шаги шкалы, подписи, `candleMove` — ход выбранной свечи для шапки истории: изменение капитала и размах из `open/close/high/low` события `select`); покрыта тестами, в том числе под тремя часовыми поясами.
- Таймфреймы: `1m 5m 15m 1h 4h` (внутридневные окна с лимитом числа свечей и подгрузкой вглубь) и `1D`, `1W` (вся история). Операция «в будущем» попадает в последнюю корзину.

## 11. Тесты и CI

- Бэкенд: `cd backend && go test ./...` — десятки сценариев в `pkg/db` (связи, баны, маски, ICU, облигации), парсеры, Binance (переводы, обмены, цены), HTTP (`routes_test.go`: каждый маршрут за CORS, защита методов, отказ на кривое и огромное тело, разбор env-списков), синхронизация (`sync_test.go`). Тестовые выписки и отчёты анонимные.
- Фронтенд: `cd frontend && bun run test` (`node --test tests/*.test.mjs`): API-слой и хранилище, реестр банков, математика графика. На Node 22 нужен glob `tests/*.test.mjs`, а не каталог.
- `.github/workflows/ci.yml` — три job'а на каждый PR и push в `dev`, `build`, `main`:
  - `backend`: проверка `gofmt -l`, `go vet`, `go test ./... -count=1`, `go build`;
  - `frontend`: `bun install --frozen-lockfile`, `bun run test`, `bun run build`;
  - `hygiene`: в git нет баз, ключей, архивов, `.env`; нет ключей и токенов (`AKIA…`, `ghp_…`, приватные ключи); нет похожих на номер карты 16-значных чисел.

Правило проверки перед «готово»: `go test ./...` и сборка фронта должны проходить.

## 12. Инварианты и ловушки

**Не менять без явной причины**

- Обработку комиссий в парсерах (Privat: `Amount` по карточной колонке; семантика комиссий Raiffeisen).
- Расширение файла в импортированном алиасе.
- Формат ключа `StableID`: иначе повторный импорт создаст дубли.
- Пары Go ↔ JS: `idKey`, `looseKey`, `isPanLike`, индекс кеша.
- `core.db` — не удалять и не пересоздавать без явной просьбы; миграции только добавляющие.
- «Стереть» в окне «Выписки» требует второго клика («Точно?»): это защита от случайного сброса.

**Решено (не возвращаться без причины)**

- Подсказки «вторая сторона перевода по времени и сумме»: пробовали несколько вариантов, они лишние и сбивают с толку.
- Автоподтяжка PAN на фронте дублировала бэкенд и не лечила баг: источник правды бэкенд.
- Банк в роли контрагента (PrivatBank, Monobank) — не человек (`isBankCounter`).

**Известные допущения**

- ICU: sell, withdraw и комиссии без образцов отчётов, чего парсер не знает, он отвергает ошибкой.
- Binance: имена операций вывода из стейкинга предположены.
- Курс USDT/UAH замораживается после даты последней «Разведки».
- NovaPay: кредитная карта пока не видела выписок.

**Скрытая связность**

- Две базы и `syncAliases`: любой код, пишущий в `core.db` из пути импорта, нарушает принцип §1.2.
- Время ICU — заглушка (полдень), порядок внутри дня задаёт `historyOrder.js`.
- Сетевая ошибка при синке: повтор того же интервала с паузой, затем офлайн; UI не сбрасывается.

## 13. Рецепты: как добавить

**Новый банк как источник выписок**
1. Парсер в `backend/pkg/<банк>/`: вернуть `[]mono.StatementItemDTO`, IBAN, карту, баланс; ID через `stmtkit.StableID`; признак `IsStatement(raw)` для автоопределения.
2. Ветка в `parseSource` (`api/sourcefile.go`) и, если нужно, тип счёта.
3. Фронт: запись в `utils/banks.js` (МФО, BIN) и цвет в `utils/bankTheme.js`; логотип в `frontend/public/banks/<МФО>.svg`.
4. Анонимные фикстуры и тесты на повторный импорт (без дублей) и на пересечение периодов.

**Новый маршрут API.** Хендлер в `pkg/api/handlers_*.go` с `allow`/`readJSON`/`writeJSON`; запись в таблице `routes.go` (CORS уже на всём mux); тест в `routes_test.go` при необходимости.

**Новый раздел бокового меню.** Компонент панели из `UiGroup`; запись `{ key, label, component }` в `utils/sections.js`.

**Новый вид операции Binance.** Правило в `ledger.go` (внешнее или внутреннее движение) → вид в `Kind*` → бейдж в `txTags.js` → тест в `binance`.
