## 1. Принципи

1. **Локально й для одного користувача.** Бекенд слухає `127.0.0.1`, перевіряє заголовок Host (захист від DNS-rebinding), CORS пускає лише перелічені Origin; тексти внутрішніх помилок повертаються клієнту (це свідомо: застосунок не публічний).
2. **Дві бази різної цінності.** `cache.db` одноразова й відновлювана, `core.db` зберігає те, що не можна втрачати (особи, аліаси, зв'язки, ручні правки). Парсери й синхронізація пишуть лише в кеш. Єдиний шлях «кеш → статика» це `syncAliases` (див. [§7](#7-особи-аліаси-звязки)).
3. **Джерело правди поза базою.** Усе, що імпортовано, лежить ще й у файлах `.zoe`; скидання кешу не губить даних (§5).
4. **Ідемпотентність.** Повторний імпорт тієї самої або перекривної виписки не створює дублів: ID операцій стабільні (`stmtkit.StableID`).
5. **Обчислюється при читанні.** Баланс ICU, накопичений купон, вид операції Binance, «власний рахунок» і `resolved_user_id` у базу не пишуться, а рахуються на льоту за поточними правилами.
6. **Явна помилка замість здогадки.** Невідомий вид операції ICU, непорожній розділ корпоративних операцій, незрозумілий файл дають помилку імпорту, а не евристику.
7. **Один механізм на одну справу.** Перед новим кодом перевіряй, чи немає вже такого шляху (HTTP-хелпери, реєстр банків, `usePaged`, `stmtkit`).

## 3. Бекенд

### 3.1 Запуск (`main.go`)

`godotenv.Load()` (необов'язково) → токени банків з `MONO_TOKENS`/`MONO_TOKEN`, `RAIF_TOKENS`/`RAIF_TOKEN` через `api.ClientsFromEnv` → `db.NewStorage(cacheDBPath, coreDBPath)` → `api.NewServer(storage, monoClients, raifClients)` → `SetBinance(binance.NewClient())` → `SetMarket(market.NewClient())` → `RestoreEconomy` і `RestoreStocks` (порожній кеш рядів чи акцій збирається з файлів групи «Экономика» (Економіка)) → `RunMarketSchedule` (знімки крипто-контуру раз на `MARKET_EVERY`, за замовчуванням година, `0` вимикає) → `ALLOWED_ORIGINS` → `http.Server` (`ReadHeaderTimeout` 10 с, `ReadTimeout` 2 хв на завантаження виписки, `IdleTimeout` 2 хв). По Ctrl+C/SIGTERM сервер дочікується запитів (10 с) і закриває обидві бази (скидання WAL). Змінні оточення: див. [README](../README.uk.md#налаштування-середовища-бекенд).

### 3.2 HTTP-шар (`pkg/api`)

- `routes.go` — **єдина таблиця маршрутів**; CORS (`EnableCORS`) навішується один раз на весь mux, тому новий маршрут не можна «забути» захистити.
- `httpx.go` — спільні відповіді: `writeJSON`, `writeOK` (`{"status":"success"}`), `writeMsg`, `fail`, `failErr` (500, текст у відповіді), `readJSON` (ліміт тіла 1 МБ, при помилці сам відповідає 400), `allow` (перевірка методу → 405). Тіла виписок читають свої хендлери (ліміт 32 МБ).
- Host: `EnableCORS` першим ділом перевіряє заголовок Host (`hostAllowed`). Своїми вважаються `localhost`, `127.0.0.1`, `::1` і хости з `ALLOWED_ORIGINS`; чуже ім'я, прив'язане до 127.0.0.1 (DNS-rebinding), отримує 403 «Host not allowed» навіть без Origin. Тести ходять на `127.0.0.1`, а не на `example.com`, який `httptest` ставить за замовчуванням.
- CORS: запит **без** `Origin` пропускається (curl, проксі); запит із невідомим Origin отримує 403.
- gzip: `gzipJSON` стискає JSON у відповідях на GET, якщо клієнт приймає gzip (швидкий рівень, пул стискачів `gzPool`).

### 3.3 Версія даних

`Storage.Version()` росте при будь-якому записі (кеш чи статика). Він віддається в `/sync/status` як `stats.data_version`. Фронт опитує легкий статус кожні 2 секунди й перезавантажує важкі дані лише при зміні версії.

## 4. Дані та бази

SQLite (драйвер `modernc.org/sqlite`, без CGO), відкривається з `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=10000`, `foreign_keys=1` через DSN (застосовується до кожного з'єднання пулу). Записи серіалізуються м'ютексами `cacheMu` і `coreMu`.

### Життєвий цикл рахунку

Банківські API дат відкриття й закриття не віддають. Відкриття = найстаріша операція, але лише коли історію знято повністю. Закриття = рахунок зник із відповіді банку (дата — остання операція). Ручна дата в `account_overrides` важливіша за виписку; після дати закриття операцій бути не може.

## 5. Джерела та імпорт

### Формат `.zoe` (`pkg/source`)

Один файл — один імпорт (або знімок API) одного рахунку за один період. Усередині **вже розібрані дані**, а не вихідний PDF/CSV: «Загрузить» (Завантажити) не парсить заново, а кладе готове в базу. Поля: `Name` (ім'я вихідного файлу = аліас, задається один раз), `Created`, `Hash` (відбиток вмісту без `Name`/`Created`/`Origin`; ті самі дані під іншим іменем — дублікат), `Kind` (`bank`, `binance`, `binance-p2p`, `icu`, `binance-series`, `dataset`), `Group` (порожньо або `accounts` — «Счета» (Рахунки); `economy` — «Экономика» (Економіка)), `Origin` (`csv`, `pdf`, `report`, `binance`, `api`), `AccountID`, `Card` (ключ теки), період (`From`/`To`), `Spans` (відрізки, уже зняті з API: після завантаження джерела синхронізація їх не опитує), плюс дані: `Txs` (банки), `Rows` (Binance), `Flows` (ICU), `Series` (хвилинний ряд Binance). Група «Экономика» зберігає таблиці рядів (`dataset`: макро-ряди й дані акцій) без рахунку: файл упізнається набором (`Card`) та ім'ям набору всередині; з них збирається кеш (`RestoreEconomy`, `RestoreStocks`, кнопка «Загрузить»). Файл пишеться атомарно (тимчасовий файл, потім перейменування) з правами `0600`; JSON більший за 1 МБ стискається gzip (читаються обидва види), розпакування обмежене 256 МБ (`maxUnpacked`, захист від gzip-бомби). Тека джерел ділиться за номером картки (`516875******8629`, не за IBAN: один IBAN може нести два PAN); `ECONOMIC_SOURCES_DIR` перевизначає шлях.

### Конвеєр імпорту

1. `POST /sources/inspect` (multipart) → `parseSource` визначає тип за вмістом: `binance.IsStatement` → Binance; `binance.IsP2P` → історія C2C-ордерів (вид `binance-p2p`, той самий рахунок `binance`, без профілю: у ній немає ідентифікатора користувача); `icu.IsReport` → ICU; PDF → Privat; `novapay.IsStatement` → NovaPay; інакше CSV Raiffeisen. Нічого не пишеться. Відповідь описує рахунок, період, перетин із наявним і список `problems`: `other_account`, `exists`, `duplicate` (блокують), `alias`, `no_match` (потребують рішення).
2. `POST /sync/import-csv` застосовує рішення користувача (`mode`, `account`, `alias`, `force`) через `enforceImportRules`, зберігає файл `.zoe` і викликає `applySource` — **єдиний шлях** і для імпорту, і для «Загрузить».
3. `applySource` пише в кеш і оновлює статику через `syncAliases`.

`migrateLegacy` переводить старі «сирі» файли кешу джерел у `.zoe`; оригінали їдуть у `_legacy`, що не розібралося, лишається й потрапляє у звіт.

### Ідентифікатори

- Банківський рахунок: `<тип>_<IBAN>`, а без IBAN `<тип>_<картка>`.
- ICU: `icu_<цифри номера договору>` (`db.ICUAccountID`): у звіті немає IBAN, договір — єдиний стабільний ключ.
- Binance: `BN<id користувача>`; профіль береться з виписки.
- Операції: `stmtkit.StableID(prefix, key, seen)`. Номер рядка файлу в ключ **не входить** (зсув рядків між вивантаженнями створював би дублікати); однакові операції в одну хвилину розрізняються порядковим суфіксом. Міняти формат ключів не можна: повторний імпорт створить дублікати.

### Парсери

| Пакет | Вхід | Особливості |
|---|---|---|
| `privat` | PDF (через `pdftext`) | сума операції береться як у картковій колонці; комісії не перераховуються |
| `raif` | CSV | семантику комісій не міняти |
| `novapay` | CSV | ПІБ, ІПН і паспорт із шапки не читаються; беруться рахунок, картка, залишок |
| `icu` | PDF (текстовий шар) | підсумки розділу 1 слугують контрольними сумами; розбіжність = відмова імпорту |
| `binance` | CSV виписки | читаються всі рядки як є; сенс рядка вирішує `ledger.go`; часовий пояс з імені файлу |

Час у виписках київський (`stmtkit.Kyiv`), не залежить від поясу сервера. Парсери й математика графіка не повинні залежати від часового поясу машини; при правках часу ганяй тести ще й під `TZ=America/New_York` і `TZ=Asia/Tokyo`.

## 6. Синхронізація по API

«Разведать» (`POST /sync/full[?save=1]`) запускає `runFullCrawler`: кожен ключ Monobank і Raiffeisen обходиться паралельно (`crawlBank` з `bankSpec`), потім за наявності виписки Binance будується хвилинний ряд оцінки (`crawlBinance`). У банків різні ліміти: Monobank — пауза 61 с між запитами одного ключа, ліміт відповіді 500 операцій; Raiffeisen — 30 с, ліміт відповіді невідомий.

**Автозапис у джерела.** З `save=1` після обходу (`saveToSources`) викликається той самий `saveAPISources`, що й у `/sources/save-api`: зняте з API пишеться у файли-джерела (повтор без нових даних нічого не плодить). Скасований обхід (скидання кешу) не пише. Підсумок іде в `last` (`autosave`, `saved`, помилки запису — у спільному списку помилок). Фронт: `useSync.js` (спільне `isSyncing`, галочка `zoe.sync.autosave`, за замовчуванням увімкнена), `SyncButton.vue` у шапці (`AppHeader`) і у вікні «Выписки», запуск — `startSync` з `App`; у бренда Ζωή пульсує крапка, поки йде синк.

**Обхід рахунку (`walkAccount`)** іде від «зараз» назад вікнами (30 днів) лише там, де `sync_coverage` не знає відповіді:

- місце вже знято → стрибок без запиту; `From == HistoryStart` → історія повністю, кінець;
- вікно, що впирається в зняте, обрізається по його краю;
- свіжий кеш = один запит (хвіст); відстав на місяць = вікна по дірі; перерване вивантаження продовжується з останньої діри;
- серія порожніх вікон оголошує початок історії; порожній знятий відрізок іде в рахунок «порожнього хвоста».

Помилки класифікуються (`errKind`): мережа (`errOffline`, решта рахунків ключа не опитується) відрізняється від відмови банку; скидання кешу скасовує обхід (`errStopped`) і не вважається збоєм. `fetchWithRetry` повторює спроби. Структурований прогрес (`progress.go`: клієнт → рахунки → таймлайн) віддається в `/sync/status`; фронт нічого не парсить із рядка статусу.

`/sync/wipe-cache` спершу знімає обхід, що йде (`abortSync`), потім чистить кеш; `core.db` не зачіпається.

## 7. Особи, аліаси, зв'язки

Словник:

- **Аліас** — ім'я з банку (власника чи контрагента); ключ `lower(trim)`. Розширення в аліасі (`Ім'я.csv`) означає «з файлу-імпорту» і **свідомо зберігається**: так IBAN такого аліаса не зливаються з однойменним API-аліасом.
- **Особа** знає лише назви своїх аліасів; усе інше йде через аліас.
- **Ефективна структура аліаса** = (статика ∪ кеш) − бани. Зелене: підтверджено кешем; жовте: лише статика.
- **Тіньовий бан** забороняє кешу підхоплювати зв'язок, який користувач прибрав вручну. Знімається при відв'язуванні аліаса чи ручному поверненні зв'язку.
- **PAN-сирота** — картка, якої немає серед власних рахунків. **Псевдо-аліас** — контрагент без імені, відомий лише за карткою.
- **Резолвер** — модалка аліаса (`AliasDrumModal`): барабан власних карток, таблиця операцій, праворуч усі картки; картка перетягується на рядок контрагента.

**Зв'язок IBAN ↔ PAN** — глобальний факт (`iban_pans`), не прив'язаний до аліаса. IBAN аліаса автоматично тягне свої картки (з `iban_pans` і кешу) мінус бани. `UnlinkAccount` банить IBAN і каскадом його картки; `LinkAccount` зобов'язаний знімати бани і з IBAN, і з його карток (регресію закрито тестом `TestRelinkIbanRestoresPans`).

**Кеш → статика**: `syncAliases` — єдиний шлях. Лише для аліасів, уже прив'язаних до Особи; лише те, що кеш підтверджує; повз тіньові бани. Викликається при старті та після імпорту/синхронізації.

**Порівняння карток**: `idKey` (перші 4 + останні 4 цифри); для масок виду `414949****72` слабкий ключ `looseKey` (BIN 6 + останні 2). **Реалізація на Go (`db/util.go`) і JS (`frontend/src/utils/personLayout.js`) має збігатися**; міняти лише парою.

**Індекс кешу** (`loadCacheIndex`, дзеркало на фронті `buildCacheIndex`): ім'я акаунта в банку → його IBAN і всі PAN; контрагент операції (`counter_name`, інакше контакт з description) → `counter_iban`. Порівняння точне, без LIKE.

**«Власний рахунок»** (`db/own.go`): номер контрагента береться з `counter_iban` і з тексту операції (ім'я/опис); рахунок самої операції не враховується; якщо номера немає, шукається за рахунками й картками аліаса, але лише коли серед них рівно один наш рахунок, окрім рахунку операції. Результат — `Transaction.OwnAccountID` (при читанні). Переказ між власними рахунками не входить у надходження/витрати ні в історії, ні в Кошторисі (Смета).

## 8. Брокер ICU та облігації

- Дані рахунку — лише брокерський звіт: журнал у `icu_flows`, баланс ніде не зберігається, а рахується з журналу та довідника облігацій (`ComputeState`).
- Види записів журналу (`icu_flows`): `deposit`, `withdraw`, `buy`, `sell`; купівля списує гроші з накопиченим купоном (`isin`, `qty`). Купони й погашення в журналі **не зберігаються**: вони обчислюються з довідника облігацій.
- Довідник `bonds` (у `core.db`, один на всіх): ISIN, назва, погашення `YYYY-MM-DD`, ставка (% річних), номінал (1000 ₴ за замовчуванням). Купон виплачується раз на 182 дні, дати відраховуються назад від погашення (`couponPeriodDays`), розмір купона = номінал × ставка / 100 / 2. Виплати (`PayEvent`, вид `coupon` або `redemption`) обчислюються при читанні; `Done` — уже минула.
- Прив'язка до Особи — звичайним шляхом, через аліас за іменем файлу.
- На фронті: `historyOrder.js` задає логічний порядок усередині дня (у звіту немає часу: полудень-заглушка, у таблиці прихований), `useCapitalChart` збирає операції облігацій у довідкові рядки (`memo`), які видно в історії, але в надходження/витрати вони не входять.

### Спільний рушій графіків (`utils/chartView.js`, `composables/useChartView.js`)

- Інтерактив SVG-графіків написано один раз. `utils/chartView.js` — чиста математика: `zoomWindow`/`panWindow` (вікно по осі X із якорем і межами розмаху), `panY`/`zoomY` (ручна вертикаль у межах крайнощів), `easeRange` (крок плавного доганяння намальованої вертикалі до цілі), `quantile` і `robustRanges` (підгонка вертикалі за перцентилями, щоб викид не сплющував шкалу, плюс `ext` — крайнощі за всіма даними).
- Колір лінії за значенням: у `SERIES` у ряду поле `gradient { from, to, stops:[[частка, колір, прозорість]] }`, `buildMacroChart` віддає `line.gradient` (вектор у пікселях графіка), `MacroPanel` малює `linearGradient` у userSpaceOnUse; зараз так забарвлені `crypto_fng` (блакитний страх — сірий середина — бурштин жадібність) і `us_vix` (сірий біля 20, вище блакитний, нижче 14 бурштиновий), `us_sentiment` — світлофор червоний (≤ 50) → жовтий (75) → зелений (≥ 100); `noLog` у ряду ховає перемикач лог-шкали.
- Шкала значення закладена в рушій: `scaleOf('linear'|'log')` (`fwd`/`inv`), `logTicks` (поділки m×10^k), `robustRanges({ log })`, `scaleTicks(mode, lo, hi)` у `growthChart.js`. Вертикаль рушія (`yShown`, `target`, `ranges`) живе в шкальному просторі (при log — натуральний логарифм), тож зсув, масштаб, плавна підгонка й інерція не знають про шкалу; `vAt` повертає звичайне значення. Графік отримує `scaleMode` і сам переводить значення через `fwd` (`buildMacroChart({ scale })`, `macroRanges({ log })`). `MacroPanel` дає перемикач і проп `log` (стартова шкала); `canLog` — усі значення > 0. `GrowthChart` і `CandleChart` поки лінійні (опція `scale` не передається), увімкнути можна так само.
- `useChartView({ width, height, pad, autoX, ranges(view, scale), spans, resetOn, bounds, inertia, scale, canLog })` тримає стан вікна й вертикалі, плавну анімацію (rAF), колесо, перетягування, наведення, скидання та переводить піксель миші в дані (`tAt`, `vAt`). Графік сам дає лише дані й межі: вікно за замовчуванням (`autoX`), діапазони вертикалі для вікна (`ranges(view)`) і функцію побудови ліній. Вісь X — роки від сьогодні (як у зростання вкладення), тому одні й ті самі `timeTicks` і `niceTicks` малюють підписи в різних графіків.
- Шар циклу Беннера: `components/BennerBands.vue` (`layer="bg"` — колонки за даними, `layer="strip"` — смуга в підвалі) + `utils/benner.js` (`bennerPhase`, `bennerSpans`); шар спільний і годиться будь-якому графіку з віссю часу (`xOf(ms) → px`, краї вікна `fromMs`/`toMs`, поля; свічки переводять слоти через `msToSlot`/`slotToMs`), але підключений лише до графіків біржі: у `MacroPanel` проп `benner` за замовчуванням `false`, `MacroStocksView` вмикає його, `GrowthChart` і `CandleChart` шар не використовують. Кольори яскраві (#fb7185 / #fbbf24 / #34d399). Це цікавинка, не сигнал (підписано в інтерфейсі).
- Підключені: `GrowthChart.vue` (зростання вкладення), `MacroPanel.vue` (макро-ряди) і `CandleChart.vue` (свічки капіталу). Пастка: змінна `dragY` оголошується до `watch(target, …, { immediate: true })`, інакше в dev TDZ. Необов'язкові можливості: `bounds()` — межі вікна по X (`clampWindow`), `inertia` — кидок убік доїжджає за інерцією (`inertiaStep`); горизонтальний жест тачпада рухає вікно, `eventT(e)` віддає вісь X під подією (клік без руху), при зсуві вікна під нерухомою мишею підказка йде за нею.

### Макро НБУ (`market/macro.go`, `db/macro.go`, `GET /api/macro`)

- Ряди FRED (джерела `us`, `usecon`, `stocks`) качає спільний `Client.fredAll` (`market/fredall.go`): пачка паралельно, не більше `fredParallel` (4) запитів одразу, результат і помилки в порядку завдань, прогрес за кількістю готових рядів. Новий ряд FRED — один рядок `fredJob{id FRED, нотатка, наш id ряду}` і власне перетворення. Денні ряди без перерахунку (DGS10, T10Y2Y, VIXCLS, NASDAQCOM, DJIA) докачуються хвостом: `Client.LastDate` (за замовчуванням `Storage.MacroLastDate`, ставиться в `Server.SetMarket`) віддає останню дату ряду в кеші, `tailStart` бере понеділок тижня за два тижні до неї й просить `&cosd=` у FRED; такий ряд потрапляє в `Result.Tail`, і `SaveMacroSeries` замінює його лише з першої дати хвоста. Ряди, що рахуються з індексу (інфляція США), і зшиті з історією (S&P 500), а також помісячні малі ряди качаються повністю. Порожній кеш — повна історія.
- Які ряди дає кожне числове джерело, оголошує саме джерело (`market.Feed.Provides`) і віддає `GET /api/macro/catalog` (`{feeds:{fx:[…]}}`); фронт (`useMacro('fx')`) бере id звідти й власних списків не тримає.
- `SaveMacroSeries` пише ряд однією транзакцією підготовленим запитом (150 тис. точок ≈ 1 с). `MacroSeries(ids)` відбирає ряди в SQL (`WHERE series IN …`): запит одного ряду на таблиці в 150 тис. точок ≈ 11 мс замість ≈ 290 мс, коли читалася вся таблиця; понад 200 ідентифікаторів — читається все й відбирається в Go.
- Джерело `macro` («Ставки та інфляція · НБУ, Євростат») у `Feeds()`. Адреси перевірено живим curl: `bank.gov.ua/NBUStatService/v1/statdirectory/key?json` — усі ставки одним запитом (щодня з 1992 року; `id_api`: `KEY_PolicyRate`, `KEY_RateOvernightCD`, `KEY_RateOvernightLoans`, поле `value`), і `…/inflation?period=m&start=YYYYMMDD&end=YYYYMMDD&json` — лише вікнами (цілком сервер відповідає 400 «надто великий dataset»); вікна по 10 років з 2000 року, дані починаються з 2007.
- Інфляція єврозони входить у джерело `macro` (`market/eu.go`, `Client.EurostatBase`, ряд `eu_cpi_yoy`, помісячно, дата — перше число місяця): SDMX-CSV Євростату `…/eurostat/api/dissemination/sdmx/2.1/data/prc_hicp_minr/M.RCH_A.TOTAL.EA?format=SDMX-CSV` (новий набір: уся історія з 1997 року до останнього місяця одним запитом; колонки `TIME_PERIOD` («2026-10»), `OBS_VALUE`; розбір терпимий до рядків різної довжини; перевірено живим curl, остання точка жовтень 2026). З лютого 2026 ЄЦБ-набір ICP і Євростат `prc_hicp_manr` заморожені на грудні 2025 — їх не використовуємо. Запит іде з явним `Accept: text/csv` і браузероподібним `User-Agent` (`getHeaders`), `Accept-Encoding: identity`, а gzip без заголовка Content-Encoding (Євростат так відповідає: тіло починається з `1f 8b`, Go сам не розпаковує) розпізнається за сигнатурою й розпаковується в `eurostatCSV`; помилка джерела `macro` при збої містить початок відповіді Євростату. Фронт: `inflationFor(currency, series)` у `utils/macro.js` (UAH — `cpi_yoy`, USD — `us_cpi_yoy`, EUR — `eu_cpi_yoy`) дає колонці «Реал.» таблиці облігацій інфляцію валюти паперу; `eu_cpi_yoy` входить у джерело `macro` (легкий набір), графік — на екрані «Инфляция».
- Ставки стискаються до дат зміни значення (`changePoints`). З інфляції беруться лише рядки підсумку: `ku` порожній, `mcrd081 = Total`, `mcrk110` порожній, назва «Індекс споживчих цін» (загальна) або «Базовий …» (базова); `tzep` `DTPY_` = р/р, `PCPM_` = до попереднього місяця; решта (ціни виробників, регіони, категорії, накопичувальні `PCCM_`/`PCCP_`) відкидається й рахується в `Skipped`.
- Збій однієї частини не стирає іншу: що завантажилося, те зберігається, помилка йде в `Result.Error`. Ряд у базі замінюється цілком (`SaveMacroSeries`), решта рядів не чіпаються.
- Фронт: `composables/useMacro.js` (читає `/macro`, перечитує за `data_version`), `utils/macro.js` (`valueAt`, `realRate` за Фішером, `macroSummary`, `buildMacroChart`), `components/MacroPanel.vue` (шар циклу Беннера, проп `benner`; поле `MACRO_PAD.b` 36 дає місце смузі); колонка «Реальная» в `MarketView` (`signed` у `COLUMNS`: нуль і мінус не вважаються «порожнім» при сортуванні).

### Ринкові облігації (`pkg/market`, `db/market.go`, `api/handlers_market.go`)

- Джерела: `https://bank.gov.ua/depo_securities?json` (реєстр, ОВДП відбираються за префіксом ISIN `UA4000`), `https://bank.gov.ua/NBU_ovdp?json&date=DD.MM.YYYY` (результати аукціонів Мінфіну; дата строго `DD.MM.YYYY`, день без аукціону дає `[]`; перебираються останні 14 днів) і `…/v1/accounting/od/auctions_query` FiscalData (аукціони США за 3 роки, CUSIP без дублів, перемагає пізніший аукціон).
- Ключів немає, запити лише на читання. Оновлення **на запит** (єдиний виняток — знімки крипто-контуру: `RunMarketSchedule` сама запускає джерело `chain` раз на `MARKET_EVERY` за сіткою часу, пропущений слот знімається при старті, при збої повтор через 2 хвилини), окремим процесом поряд з обходом банків: запускається разом з «Разведать» (`POST /api/sync/full`, навіть якщо в банків немає ключів) або сам (`POST /api/market/sync[?source=nbu|ust]`, відповідь одразу, 409 якщо вже йде). Список — `GET /api/market/bonds[?source=&q=]`.
- Джерела — «фіди» (`market.Feed`: `ID`, `Title`, `Fetch`, список `Client.Feeds()`): ідуть **паралельно** й не знають одне про одного, той, що впав, не заважає іншому. Нове джерело (ФРС тощо) — ще один запис у `Feeds()`, без нових маршрутів і тостів. Фід паперів заповнює `Fetch` (`[]Security` → `market_bonds`), фід числових рядів — `Series` (`[]SeriesPoint` → `macro_series`, `Storage.SaveMacroSeries`), у фіда є `Unit` («паперів»/«точок») для вікна процесу й тоста; `?source=` перевіряє `market.IsSource`.
- Стан — ключ `market` у `/api/sync/status` (`running`, `started_at`, `feeds[]` зі `state` `queued|fetch|done|error`, `fetched`, `skipped`, `error`, і `last` з підсумком). Він **не змішаний** з банківським `progress`: свій підсумок, власне блокування і власний контекст скасування. Скидання кешу (`abortSync`) скасовує й цей процес та чекає його до 3 с, щоб він не дописав дані в чисту базу.
- Перебіг: `Feed.Fetch(ctx, rep Reporter)`; джерело повідомляє `rep(pct, note)` («аукціони: 07.11», 46 %). У `feeds[]` це `pct`/`note`: з відсотком фронт малює заливку, без відсотка (`pct` 0) — біжучі смуги. Для довгих вивантажень (наприклад, помісячна ставка США за багато років) джерело просто викликає `rep`.
- Вікно процесу: `MarketPanel.vue` (у `ToastStack`) висить, поки `market.running`, як вікно синку банків, але окреме; хрестик глушить саме цей запуск (`started_at`). Логіка показу — `utils/marketPanel.js` (`marketPanelOpen`, `feedView`).
- Фронт: `utils/marketNotice.js` вирішує, що показати, за `market.last.finished_at` (підсумок до перезавантаження сторінки не показується); на кожне джерело свій тост: зелений за таймером або червоний до закриття.
- Розбір поблажливий: поле шукається за кількома іменами, `null`/порожньо — немає значення, число приймає `16,44`. Запис без ідентифікатора пропускається (`Result.Skipped`). Формати звірено за документацією, а не за живою відповіддю, тому при зміні полів джерела правиться список імен у `nbu.go`/`ust.go`.
- Збереження — `ON CONFLICT … DO UPDATE`: порожнє значення не затирає відоме (реєстр дає умови, аукціон — дохідність). Погашені папери лишаються. `WipeCache` стирає й цю таблицю.
- Зв'язок з ICU: `bondTerms()` бере довідник `core.bonds` і додає завантажені гривневі ОВДП зі ставкою > 0 та датою погашення; **власний запис завжди важливіший за завантажений**. Редактор довідника (`ListBonds`, `/api/icu/bonds`) показує лише власні записи.
- Автозаповнення: форма «+ ОВДП» у редакторі довідника (`IcuBondsEditor.vue`) за 12-значним ISIN запитує `GET /api/market/bonds?source=nbu&q=<ISIN>`, шукає **точний** збіг (`utils/bondLookup.js`) і підставляє лише порожні поля: погашення, ставку, назву; набране руками не затирається, безкупонний ставку не заповнює. Немає в кеші — підказка «натисни «Разведать» або введи вручну».
- Решта джерел білда 2 (США з FRED, країни й єврозона, сировина, світові акції, акції компаній, крипто й крипто-контур, купівельна спроможність) влаштовані так само: один фід, свої ряди, реєстрація в `Feeds()`; каталог рядів і реєстр країн віддає `GET /api/macro/catalog`, здоров'я джерел — `GET /api/macro/sources`.

## 9. Binance

Джерело рухів — лише офіційна виписка (Wallet → Transaction History → Export); ключа API немає. Публічні ціни беруться з `api.binance.com` (хвилинні свічки, `Prices`, `Symbols`); клієнт дотримується лімітів і повторює запити.

- `p2p.go` читає історію C2C-ордерів (Orders → P2P → Export): позиційно, усі ордери як є, комісія мейкера й тейкера сумується в монеті; на гаманець приходить `Qty − Fee` (це число й лежить P2P-рядком у журналі виписки, за кілька хвилин після створення ордера). Це доповнення до виписки: власний `.zoe` виду `binance-p2p`, ім'я рахунку, профіль і покриття осі не змінює, ордери в кеші (`binance_p2p`) переживають лише до скидання й повертаються «Загрузить».
- `statement.go` читає всі рядки; `ledger.go` вирішує, що рядок означає для портфеля: зовнішні рухи (депозит, виведення, P2P, бонус, dividend) стають операціями рахунку, решта (угоди, комісії, конвертації, пил, стейкінг) лишається внутрішнім рухом гаманця.
- Гаманці: Spot, Funding, Strategy, USD-M Futures — **усі чотири** вважаються частиною портфеля за ринковою ціною, тому графік рухається по ходу роботи ботів і ф'ючерсів. Earn у виписці власних рядків не має й видно за підпискою/викупом.
- `moves.go` збирає перекази між гаманцями: два рядки журналу (мінус в одному, плюс в іншому) парляться за монетою й сумою у вікні кількох секунд; одинока половина добудовується за назвою операції. Це довідкові рядки історії («звідки → куди»), капітал не змінюють. `swaps.go` — обміни (Convert, пил → BNB, стейкінг), `trades.go` — купівлі й продажі.
- `series.go`: залишки відомі з журналу на будь-який момент (`Timeline`), історія портфеля = оцінка залишків за хвилинними свічками монет і парою USDT/UAH. Ряд підписано хешем журналу (`Sig`): змінився журнал — ряд застарів. Після нового CSV ряд обрізається з хвилини першого **нового** рядка й домальовується; повтор того самого CSV ряд не чіпає; новий рядок раніше за початок ряду — ряд з нуля.
- Баланс рахунку = остання точка ряду. На картці Binance показується в доларах з еквівалентом у гривнях (курс USDT/UAH з останньої «Розвідки»).
- «Сброс кеша» (Скидання кешу) зносить і Binance; «Загрузить» повертає журнал із `.zoe`, наступна «Розвідка» будує оцінку. Ряд зберігається в `.zoe` як `binance-series` (збір займає 10–20 хвилин).

## 10. Фронтенд

Vue 3 (`<script setup>`), Tailwind v4, Vite, bun. Без роутера й без стору: стан живе в `App.vue` та composables; вкладки в `KeepAlive`.

### 10.1 Потік даних

```
setInterval 2 с → GET /sync/status → stats.data_version змінилась?
                                     └─ так → fetchData(): /accounts /transactions /users …
```

`App.vue` тримає `accounts`, `transactions`, `users`, прогрес синхронізації й передає їх у вкладки як props. Тости (`useToasts`) показують підсумок синку. Втрата зв'язку з бекендом — окрема плашка, не «синк упав».

### 10.2 API-шар (`utils/api.js`)

Єдине місце з `fetch`: `API_BASE` (`VITE_API_BASE`, за замовчуванням `http://127.0.0.1:8080/api`: `localhost` міг іти на IPv6 у чужу програму), `apiSend(method, path, body)` (JSON), `apiUpload` (multipart), `apiGetJson`, `apiJson`, `q` (= `encodeURIComponent`). Помилка не-2xx перетворюється на `Error` з текстом бекенду. Прямих `fetch` у компонентах бути не повинно.

### 10.3 Браузерне сховище (`utils/storage.js`)

`storageGet/storageSet/loadJSON/saveJSON` — безпечні обгортки над `localStorage` (приватне вікно, очищені дані: не кидають). Використовуються лише для зручностей: активна вкладка (`economic_active_tab`), таймфрейм (`zoe.candle.tf`), порядок карток (`persons_card_order`). Усе, що важливо зберегти, живе на бекенді.

### 10.4 Сторінки (`views/`)

Верхніх вкладок у шапці немає: шапка — бічне меню, бренд Ζωή (повернення на Головну) і «Разведать» (Розвідати). колесо/перетягування/подвійний клік; вертикаль гібридна: `yRanges` дає `auto` (під вікно) і `ext` (крайнощі), ручний зсув/Shift+колесо тримається в `ext`, а намальований діапазон доганяє ціль через rAF; розрив Топ 1/Топ 5 за 10 р. за валютами рахує `MarketView` і передає пропом `spreads`) |
| Учёт (Облік) | `data` | `DataView`: список розділів за лівим краєм основної сітки (підписи від 1380px, іконки від 1240px, нижче рядком зверху), праворуч вибраний екран |

Список розділів — спільний компонент `SectionRail` (підтримує групи `{key,label,icon,children}`: заголовок із шевроном лише в широкому режимі, відкритість групи пам'ятається під `groups-key`, група вибраного розділу розкривається сама; пласкі списки працюють як раніше). Ринок: оболонка `MarketView` (шторка, `useMacro` один раз, `KeepAlive` для `BondsView`) + екрани `BondsView` (розділ `nbu`/`ust` пропом), `MacroRatesView`, `MacroInflationView` на універсальному `MacroPanel` (props `ids`, `unit`, `title`, слот `summary`; вікно за замовчуванням — увесь період, далі колесо, перетягування та «Сброс масштаба» (Скинути масштаб)); дерево розділів і `feedOf` — `utils/marketNav.js` (у розділу поле `feed`: ставка й інфляція — `macro`, «Курсы» — `fx`, «Ставка ФРС» — `us`; `MacroFxView` читає ряди окремим `useMacro('fx')` лише на своєму екрані), решта макро-екранів (`Macro*View.vue`) влаштовані так само (`MarketHeader` і `MacroPanel`-и), а повний список розділів, їх `feed` і значки веде лише `MACRO_SECTIONS` у `utils/marketNav.js` (тут він не дублюється); «Обновить» (Оновити) — `composables/useMarketRefresh.js` (`POST /market/sync?source=`, для макро-екранів `macro`) (підписи / колонка іконок / рядок зверху), вибір розділу й позиція прокручування — `composables/useSection.js`; ним користуються «Учёт» і «Рынок» (ключ розділу ринку `economic_market_section`, оновлення за `data_version`, запуск опитування `POST /market/sync?source=`). Розділи «Учёта» (ключ в `economic_data_section`): **История** (`history`, `OperationalView`: плитки рахунків з мультивибором + графік + історія операцій) і **Лица** (Особи) (`persons`, `PersonsView`: граф аліасів, безгосп, редактор зв'язків, барабан; лічильник людей поруч з назвою). Обидва екрани у своєму `KeepAlive`, у кожного своя позиція прокручування. Старі значення `accounts`/`entities` в `economic_active_tab` переводить `utils/nav.js` (`resolveNav`) і одразу переписує в новому вигляді. Нова сторінка верхнього рівня = запис у `TOP_TABS` і `ARCHIVE_PAGES` (`utils/nav.js`) та гілка в `App.vue`; новий розділ даних = запис у `SECTIONS` у `DataView`.

Компоненти з прокручуванням чи виміром розмірів усередині `KeepAlive` зобов'язані пересинхронізуватися в `onActivated`: прихований блок втрачає `scrollLeft` без події (так лагодився `CandleChart`; зараз він прокручування не використовує).

Бічне меню будується з реєстру `utils/sections.js` (зараз два розділи: «Архив» — розділ-навігатор, `pages: ARCHIVE_PAGES`, клік перемикає сторінку застосунку; і «Управление» (Керування) → `DebugSection`, у ньому вікно «Выписки»). Новий розділ = один запис у реєстрі.

### 10.5 Граф аліасів (`utils/personLayout.js`)

Головна клієнтська логіка: з `users`, `alias-structures`, рахунків і транзакцій будується граф — для кожної Особи групи банків, IBAN, картки, підтвердженість, PAN-сироти. Містить дзеркало бекенду (`idKey`, `looseKey`, `isPanLike`, `buildCacheIndex`): **міняти разом із `db/util.go` і `db/resolve.go`**. `resolveRows.js` готує рядки резолвера (вихідні: лише перекази людям; вхідні: усе, крім юрособ і магазинів; банк як «контрагент» — комісія, не людина). `personName.js` підміняє аліас контрагента на Особу: хто чий, вирішує бекенд (`resolved_user_id`), фронт лише підставляє.

### 10.6 Свічковий графік

- `composables/useCapitalChart.js` збирає вхід: гривневі рахунки, їхні операції, крипто-рахунки, операції облігацій (`bondOps`) і виплати (`payEvents`). `pickedIds` порожній — усі рахунки (Смета), інакше вибрані картки (Операційна).
- `components/CandleChart.vue` — реактивна частина: таймфрейми, підвантаження свічок Binance чанками (кеш за таймфреймом), вибір свічки кліком. Масштаб, зсув, інерцію й вертикаль веде спільний рушій (`useChartView`): вісь X — слоти від правого краю даних (`candleBounds`, `candleWindow`, `candleSpans`, `visibleSlots`, `candleYRanges` у `utils/candleMath.js`), тому підвантаження історії ліворуч вікно не рухає; малюються лише видимі свічки плюс слот запасу; вертикаль за свічками у вікні, ручний зсув і Shift+колесо в межах крайнощів; ширина svg вимірюється `ResizeObserver` (прихована вкладка в `KeepAlive` дає 0 — тримається попередня). Колесо над ним обробляється самим компонентом (`data-wheel="own"`).
- `utils/candleMath.js` — **чиста математика без Vue і DOM** (таймфрейми `TFS`, початки дня/тижня, кошики, «гарні» кроки шкали, підписи, `candleMove` — хід вибраної свічки для шапки історії: зміна капіталу й розмах з `open/close/high/low` події `select`); покрита тестами, зокрема під трьома часовими поясами.
- Таймфрейми: `1m 5m 15m 1h 4h` (внутрішньоденні вікна з лімітом числа свічок і підвантаженням углиб) та `1D`, `1W` (уся історія). Операція «в майбутньому» потрапляє в останній кошик.

### 10.8 Правила продуктивності (аудит `v1.2.103`–`v1.2.112`)

- Макро-ряди (`useMacro`, `useCountries`) лежать у `shallowRef`, не в `ref`: глибока реактивність обгортала кожну точку в Proxy, і читання рядів (індекс долара, «Курсы») ішло в десятки разів повільніше. Ряд замінюється цілком, на місці не змінюється.
- `utils/macro.js`: числовий індекс ряду (`indexOf`, кеш у `WeakMap` з перевіркою довжини й останньої точки) і бісекція вікна (`firstFrom`) замість перебору всіх точок; щільна лінія проріджується за стовпцями (`thinColumns`); `robustRanges` сортує типізований масив.
- `Intl.NumberFormat` створюється один раз на модуль (≈29 мкс на створення проти ≈0,5 мкс на повторне використання): не створювати форматери в циклах і шаблонах.
- `MarketView` тримає `feedStamps(() => dataVersion)`: розділ, відкритий до запису даних у кеш, перечитується при поверненні.
- `macro_series` — кластерна таблиця (`WITHOUT ROWID`, §4), JSON-відповіді стискаються швидким gzip із пулом (§3.2).

## 11. Тести та CI

- Бекенд: `cd backend && go test ./...` — десятки сценаріїв у `pkg/db` (зв'язки, бани, маски, ICU, облігації), парсери, Binance (перекази, обміни, ціни), HTTP (`routes_test.go`: кожен маршрут за CORS, захист методів, відмова на криве й величезне тіло, розбір env-списків), синхронізація (`sync_test.go`). Тестові виписки й звіти анонімні.
- Фронтенд: `cd frontend && bun run test` = `node --test tests/*.test.mjs && vitest run`: чиста логіка (API-шар, реєстр банків, математика графіків, макро, формати) на `node --test`, компоненти на vitest з happy-dom (`tests/components`). На Node 22 потрібен glob `tests/*.test.mjs`, а не каталог. У `package.json` заведено `overrides` для `glob` і `minimatch` (вразливості транзитивних devDependencies): `bun audit` чистий, `bun.lock` оновлюй разом із ними.
- `.github/workflows/ci.yml` — три job'и на кожен PR і push у `dev`, `build`, `main`:
  - `backend`: перевірка `gofmt -l`, `go vet`, `golangci-lint` (v2.15.0, конфіг `backend/.golangci.yml`), `go test ./... -count=1`, `go build`;
  - `frontend`: `bun install --frozen-lockfile`, `bun run test` (node і vitest), `bun run build`;
  - `hygiene`: у git немає баз, ключів, архівів, `.env`, `.commits/`, `.claude`; немає ключів і токенів (`AKIA…`, `ghp_…`, приватні ключі); немає схожих на номер картки 16-значних чисел у `backend` і `frontend/src` (тестові заглушки — в allowlist усередині `ci.yml`).

Правило перевірки перед «готово»: `go test ./...`, `golangci-lint run`, `bun run test` і збірка фронту мають проходити.

## 12. Інваріанти та пастки

**Не міняти без явної причини**

- Обробку комісій у парсерах (Privat: `Amount` за картковою колонкою; семантика комісій Raiffeisen).
- Розширення файлу в імпортованому аліасі.
- Формат ключа `StableID`: інакше повторний імпорт створить дублікати.
- Пари Go ↔ JS: `idKey`, `looseKey`, `isPanLike`, індекс кешу.
- `core.db` — не видаляти й не перестворювати без явного прохання; міграції лише додавальні.
- «Стереть» (Стерти) у вікні «Выписки» вимагає другого кліку («Точно?» — Точно?): це захист від випадкового скидання.

**Вирішено (не повертатися без причини)**

- Підказки «друга сторона переказу за часом і сумою»: пробували кілька варіантів, вони зайві й збивають з пантелику.
- Автопідтяжка PAN на фронті дублювала бекенд і не лікувала баг: джерело правди бекенд.
- Банк у ролі контрагента (PrivatBank, Monobank) — не людина (`isBankCounter`).

**Відомі припущення**

- ICU: sell, withdraw і комісії без зразків звітів, чого парсер не знає, він відхиляє помилкою.
- Binance: імена операцій виведення зі стейкінгу припущено.
- Курс USDT/UAH заморожується після дати останньої «Розвідки».
- NovaPay: кредитна картка поки не бачила виписок.

**Прихована зв'язність**

- Дві бази й `syncAliases`: будь-який код, що пише в `core.db` зі шляху імпорту, порушує принцип §1.2.
- Час ICU — заглушка (полудень), порядок усередині дня задає `historyOrder.js`.
- Мережева помилка при синку: повтор того самого інтервалу з паузою, потім офлайн; UI не скидається.

## 13. Рецепти: як додати

**Новий банк як джерело виписок**
1. Парсер у `backend/pkg/<банк>/`: повернути `[]mono.StatementItemDTO`, IBAN, картку, баланс; ID через `stmtkit.StableID`; ознака `IsStatement(raw)` для автовизначення.
2. Гілка в `parseSource` (`api/sourcefile.go`) і, якщо треба, тип рахунку.
3. Фронт: запис у `utils/banks.js` (МФО, BIN) і колір у `utils/bankTheme.js`; логотип у `frontend/public/banks/<МФО>.svg`.
4. Анонімні фікстури й тести на повторний імпорт (без дублів) та на перетин періодів.

**Новий маршрут API.** Хендлер у `pkg/api/handlers_*.go` з `allow`/`readJSON`/`writeJSON`; запис у таблиці `routes.go` (CORS уже на всьому mux); тест у `routes_test.go` за потреби.

**Новий розділ бічного меню.** Компонент панелі з `UiGroup`; запис `{ key, label, component }` у `utils/sections.js`.

**Новий вид операції Binance.** Правило в `ledger.go` (зовнішній чи внутрішній рух) → вид у `Kind*` → бейдж у `txTags.js` → тест у `binance`.
